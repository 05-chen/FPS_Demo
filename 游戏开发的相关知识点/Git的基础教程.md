## 1. Git 核心底层模型

在使用 Git 命令之前，脑海里必须有 Git 的 **“四个工作区域”**：

```
[ 工作区 (Working Directory) ] ──(git add)──> [ 暂存区 (Stage/Index) ]
                                                       │
                                                 (git commit)
                                                       ▼
[ 远程仓库 (Remote Server) ] <───(git push)─── [ 本地仓库 (Local Repository) ]
```

- **工作区**：你在电脑文件夹里能看到的代码文件（你在 Godot / VS Code 里修改的文件）。
- **暂存区**：临时存放修改的地方（就像搬家时打好的包裹）。
- **本地仓库**：保存在你自己电脑上的完整历史版本库（`.git` 隐藏文件夹）。
- **远程仓库**：托管在 GitHub / Gitee / GitLab 上的云端仓库。



## 2. 第一阶段：从零开始上传项目（个人单机模式）

这是将本地项目初次上传到 GitHub / Gitee 的**完整标准步骤**：

### Step 1: 环境初始化（第一次安装 Git 后配置一次即可）

Bash

```
git config --global user.name "你的名字/昵称"
git config --global user.email "你的邮箱@example.com"
```



### Step 2: 在本地项目根目录初始化 Git

打开终端/命令行，切换到你的项目文件夹：

Bash

```
git init
```

*(此时文件夹下会生成一个隐藏的* `.git` *文件夹)*

### Step 3: 配置 `.gitignore` 忽略文件（极其重要！）

在项目根目录创建一个名为 `.gitignore` 的文件，写入不需要上传的文件类型（如日志、临时编译文件、缓存）。

### Step 4: 将代码添加至暂存区并提交到本地仓库

Bash

```
# 1. 把当前目录所有文件加到暂存区（注意有个点）
git add .   

# 2. 提交到本地仓库，并附带本次修改的说明
git commit -m "feat: 项目初次提交/完成初始框架搭建"
```



### Step 5: 关联远程仓库并推送

1. 在 GitHub / Gitee 上新建一个空白仓库（**不要**勾选“Initialize this repository with a README”）。
2. 复制远程仓库的 HTTPS/SSH 地址。
3. 执行终端命令：

Bash

```
# 1. 关联远程仓库，并将地址命名为 origin
git remote add origin https://github.com/你的用户名/仓库名.git

# 2. 将本地默认分支重命名为 main (如果默认就是 main 可省略)
git branch -M main

# 3. 将本地代码推送到远程 main 分支，-u 参数会建立本地与远程的跟踪关系
git push -u origin main
```



## 3. 第二阶段：团队协作开发工作流（多人打团模式）

在团队中，**绝对禁止直接向** `main` **分支提交代码**。推荐采用 **Feature Branch（功能分支）工作流**：

```
[ 远程 main 分支 ] (只存放绝对稳定的代码)
       │
       ├─ (Git Checkout) ──> [ 你的分支 feature/player-ui ] ──(开发+Commit)──┐ (发起 PR/MR)
       │                                                                 ▼
       └─ (Git Checkout) ──> [ 队友分支 feature/network ] ──(开发+Commit)──┴──> 合并回 main
```



### 团队协作 5 步走：

1. **同步最新代码**：每天开工前，拉取最新的主干代码：
  Bash
2. **新建专属功能分支**：基于最新的 `main` 创建你的任务分支（如 UI 界面、网络模块）：
  Bash
3. **本地写代码并提交**：
  Bash
4. **推送到远程分支**：
  Bash
5. **发起 PR / MR（Pull Request / Merge Request）**：
  - 登录 GitHub/Gitee 网页界面，点击 **"New Pull Request"**。
  - 邀请组长/同事做 **Code Review（代码审查）**，测试通过后由组长合并进 `main`。



## 4. 第三阶段：高频命令与分支管理



### 🔍 查看状态与历史

- `git status`：查看当前代码状态（哪些文件被修改了、哪些文件还在暂存区）。
- `git log`：查看提交的历史记录（日志）。
- `git log --oneline --graph`：用精简的树状图展示分支提交历史（非常直观）。



### 🌿 分支（Branch）操作

- `git branch`：查看本地所有分支。
- `git branch -a`：查看本地和远程的所有分支。
- `git branch <分支名>`：创建新分支。
- `git checkout <分支名>` 或 `git switch <分支名>`：切换分支。
- `git checkout -b <分支名>`：**创建并直接切换**到该分支（最常用）。
- `git branch -d <分支名>`：删除已合并的本地分支。



## 5. 第四阶段：冲突解决与保命回滚



### ⚔️ 冲突产生与解决（Merge Conflict）

**原因**：当两个人同时修改了同一个文件的同一行代码，Git 无法决定听谁的。

**解决 3 步法**：

1. **拉取最新主干代码尝试合并**：
  Bash
2. **打开编辑器查找冲突标记**：
  编辑器会将冲突位置标注出来：
   C#
   **人工裁决**：删除多余的 `<<<<<<<`、`=======`、`>>>>>>>` 符号，保留真正需要的代码。
3. **重新提交解完冲突的代码**：
  Bash



### 🚑 撤销与“保命”回滚命令


| **需求场景**                             | **推荐命令**                           | **作用效果**                                 |
| ------------------------------------ | ---------------------------------- | ---------------------------------------- |
| **刚改了代码，想放弃工作区的修改（还没 add）**          | `git checkout .` 或 `git restore .` | 彻底丢弃本地未保存的修改，还原到上一次提交状态。                 |
| **已经** `git add` **了，想从暂存区撤回**       | `git restore --staged <文件名>`       | 把文件移出暂存区，但保留本地代码修改。                      |
| **刚写完 Commit，发现少加了一个文件或 Commit 写错了** | `git commit --amend`               | 修正上一次 Commit 的内容或注释，不产生新的提交记录。           |
| **想彻底回退到过去某个 Commit（危险操作！）**         | `git reset --hard <commit-id>`     | **物理抹杀**！把代码彻底重置到历史某个版本，之后的提交全部丢失！       |
| **想要安全地撤销过去的某个 Commit**              | `git revert <commit-id>`           | **推荐**！新建一次 Commit 来抵消掉过去的那次修改，历史记录依然完整。 |




## 6. 第五阶段：游戏开发（Godot/Unity）专属避坑指南

游戏开发项目因为包含大量二进制文件、资源贴图和引擎生成的缓存，使用 Git 时需要特别注意：

1. **必须配置专属的** `.gitignore`：
  - **Godot 项目**：必须忽略 `.godot/` 导入缓存目录（该目录体积庞大，且每个人电脑上可以自动生成）。
  - **Unity 项目**：必须忽略 `Library/`、`Temp/`、`Logs/` 目录。
2. **启用 Git LFS（Large File Storage 大文件存储）**：
  - 游戏里的 `.wav`、`.mp4`、`.psd`、`3D 模型` 等几百兆的文件**不要直接进普通 Git 提交**，否则仓库几个 GB 会直接卡死。使用 Git LFS 可以只托管这些大文件的指针。
3. **场景文件解耦（减少冲突）**：
  - 尽量不要所有人都去改同一个主场景（如 `Main.tscn`），多用子场景（PackedScene/Prefab）组合，把角色、UI、环境分离开，能避免 90% 难搞的场景文本冲突。
